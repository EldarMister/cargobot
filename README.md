# BCL EXPRESS — Telegram-бот карго-доставки

Асинхронный Telegram-бот для регистрации клиентов, привязки существующих J-кодов,
импорта посылок из Excel и управления их статусами. Основной идентификатор владельца
во всей системе — `client_code`; имя и Telegram username для привязки посылок не используются.

## Возможности

- регистрация нового клиента с автоматическим кодом `J-0001`, `J-0002`, …;
- защищённая привязка заранее созданного клиента по J-коду и точному ФИО;
- автоматическое присоединение ранее импортированных посылок после регистрации;
- личное меню, список посылок по статусам, адрес китайского склада и проверка трека;
- Telegram-админка: Excel-импорт, клиенты, посылки, статусы, даты, настройки, статистика и рассылка;
- чтение всех листов `.xlsx` и `.xls`, журнал каждой строки импорта;
- идемпотентное обновление по уникальному трек-коду и история смены статусов;
- уведомления только при появлении посылки, реальной смене статуса или даты доставки;
- PostgreSQL, FSM в памяти, Alembic, Docker Compose и тесты.

## 1. Создание бота и получение токена

1. Откройте в Telegram официальный аккаунт `@BotFather`.
2. Выполните команду `/newbot`, задайте имя и username, заканчивающийся на `bot`.
3. BotFather выдаст токен вида `123456:ABC...`. Это значение `BOT_TOKEN`.
4. Не публикуйте токен и не добавляйте рабочий `.env` в Git.

## 2. Telegram ID администратора

Узнать свой числовой Telegram ID можно через информационного бота (например, `@userinfobot`)
или временно посмотреть `message.from_user.id` в отладочном обработчике. В `.env` разрешено
несколько администраторов через запятую:

```env
ADMIN_IDS=123456789,987654321
```

После запуска админ открывает панель командой `/admin`. Каждый admin handler дополнительно
защищён фильтром по этому списку.

## 3. Настройка `.env`

Скопируйте пример и заполните секреты:

```powershell
Copy-Item .env.example .env
```

Минимально задайте `BOT_TOKEN`, `ADMIN_IDS` и подключение к PostgreSQL одной переменной:

```env
DATABASE_URL=postgresql+asyncpg://cargo:password@localhost:5432/cargo
```

На Railway достаточно ссылки `DATABASE_URL=${{Postgres.DATABASE_URL}}`: приложение само
подставит асинхронный драйвер. Redis не требуется. Незавершённый пошаговый диалог сбросится
при перезапуске процесса, но постоянные данные пользователей и посылок останутся в PostgreSQL.

## 4. Запуск через Docker

Требуются Docker Desktop и Compose:

```powershell
docker compose up -d --build
docker compose logs -f bot
```

Контейнер `bot` ждёт healthcheck PostgreSQL, затем автоматически выполняет
`alembic upgrade head` и запускает polling. Остановка без удаления данных:

```powershell
docker compose down
```

Именованный volume `postgres_data` сохраняет базу. Команда
`docker compose down -v` удалит их без возможности восстановления и для обычной остановки
не нужна.

## 5. Локальный запуск

Нужны Python 3.12+ и работающий PostgreSQL.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
alembic upgrade head
python -m app.main
```

Миграции вручную:

```powershell
alembic current
alembic upgrade head
```

Создавать таблицы через `Base.metadata.create_all()` в production не нужно — схема
управляется только Alembic.

## 6. Первичная настройка в Telegram

1. Администратор выполняет `/admin` → `⚙️ Настройки`.
2. По очереди задаёт название компании, стандартный срок доставки, получателя, телефон,
   китайский адрес, название склада и поддержку. По умолчанию используются `BCL EXPRESS`
   и расчётный срок `12 дней`.
3. При необходимости заранее создаёт клиента через `➕ Добавить клиента`.
4. Клиент выполняет `/start`, регистрируется или привязывает выданный J-код.

Один J-код автоматически привязывается только к одному Telegram ID. Снять привязку может
администратор через поиск клиента. После пяти неправильных попыток проверки ФИО FSM сбрасывается.

## 7. Импорт Excel

1. `/admin` → `📥 Загрузить Excel`.
2. Выберите статус, который соответствует всей загружаемой партии.
3. Для статуса `🚚 В пути` укажите дату выезда или нажмите `📅 Сегодня`. Примерную дату
   прибытия можно ввести вручную либо рассчитать автоматически по стандартному сроку.
4. Отправьте `.xls` или `.xlsx` документом.
5. Проверьте статус, даты и имя файла в предпросмотре, затем нажмите `✅ Импортировать`.

Импортёр проходит все листы, нормализует `j - 8226` в `J-8226`, сохраняет числовые треки
строками и пропускает заголовки, пустые строки, даты и некорректные пары. По завершении бот
показывает количество новых, обновлённых и пропущенных строк; причины пропуска доступны
отдельной кнопкой.

Если трек уже существует, новая запись не создаётся. Обновляются владелец, статус, явно
указанные даты и ссылка на последний импорт. Пропущенные даты не очищают сохранённые значения.
Полностью одинаковые статус и даты не добавляют историю и не вызывают уведомление. Изменение
только примерной даты прибытия отправляет отдельное уведомление без лишней записи истории
статусов.

Даты партии сохраняются также в таблице `imports`, поэтому параметры массового обновления
можно восстановить по журналу. Старые посылки с пустыми датами продолжают отображаться без
фиктивных значений.

После отправки бот один раз напоминает клиенту о приближении расчётной даты за три дня,
а при наступлении даты сообщает, что точное прибытие уточняется. Расчёт никогда не меняет
статус на `Прибыл` автоматически. Когда машина фактически приехала, администратор нажимает
`🏢 Отметить партию прибывшей` в сообщении о завершённом импорте и подтверждает действие.
Все товары партии переходят в статус `🏢 Прибыл`, история сохраняется, а привязанные клиенты
получают уведомления. Повторное подтверждение и повторные напоминания не рассылаются.

Для отдельного товара используйте `/admin` → `🔎 Найти трек`: карточка позволяет изменить
статус, дату выезда и примерную дату прибытия. Клиент уведомляется только при фактическом
изменении.

## 8. Тесты и проверка кода

```powershell
python -m pip install -r requirements-dev.txt
pytest -q
ruff check .
python -m compileall -q app tests
```

Тесты используют SQLite только как изолированную in-memory среду; production-конфигурация
всегда работает с PostgreSQL.

## 9. Резервное копирование PostgreSQL

Создать backup из Docker-контейнера:

```powershell
docker compose exec -T postgres pg_dump -U cargo -d cargo -Fc > cargo_backup.dump
```

Восстановление в пустую БД (операция перезаписывает конфликтующие объекты, сначала сохраните
текущие данные):

```powershell
Get-Content -AsByteStream cargo_backup.dump | docker compose exec -T postgres pg_restore -U cargo -d cargo --clean --if-exists
```

Периодически проверяйте восстановление резервной копии на отдельной тестовой БД.

## 10. Архитектура

```text
app/
  bot/handlers/{user,admin}/  Telegram handlers и FSM-сценарии
  bot/keyboards/              Reply/Inline keyboards
  bot/middlewares/            транзакционная DB session на update
  core/                       конфигурация, enum и logging
  db/models/                  SQLAlchemy 2 models
  db/repositories/            запросы к данным
  services/                   Excel, import, users, parcels, notifications
  main.py                     точка запуска
alembic/                      миграции PostgreSQL
tests/                        unit и service tests
```

`ExcelImporter` не зависит от aiogram. Для будущего API перевозчика предусмотрен протокол
`TrackingProvider`; текущая версия не симулирует GPS и меняет реальные статусы только по
действию администратора.

## Эксплуатационные замечания

- Настройте ограниченный доступ к серверу и не публикуйте порт PostgreSQL наружу.
- Обновляйте зависимости и образы после проверки в тестовой среде.
- В логах намеренно нет BOT_TOKEN и паролей; логи действий содержат только необходимые ID.
- Если пользователь заблокировал бота, уведомление/рассылка продолжатся для остальных адресатов,
  а ошибка будет записана в лог без остановки процесса.
